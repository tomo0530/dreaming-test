## 1. 主仮説（1 つ）

> H1: SchemaDrift-SQL の実行一致率において、A4（transcript で裏付けを取る Dreaming）は A1（transcript を読める Rolling Summary、同一モデル・同一予算）を上回る。

- 推定量: Δ = mean_s [acc_s(A4) − acc_s(A1)]（s はストリーム、acc は当該ストリームの全問正答率）。
- 区間: ストリームを再標本化単位とする paired bootstrap、10,000 回、パーセンタイル法 95% CI。bootstrap の乱数 seed は 20261110。
- 判定: CI 下限 > 0 → H1 を支持。CI が 0 を含む → 「優位を示せない」。CI 上限 < 0 → 「A1 が上回った」。
- 実務上の目安: Δ ≥ +0.05。目安に届くかは点推定で併記するが、判定には使わない。
- 主張の範囲: A4 と A1 は記憶システム全体として比較する。A4 はオンラインでメモを書けるが A1 は書けないため、Δ にはセッション内のメモ書きの効果も含まれる。オフライン処理は合計ターン数・累計入力上限・`reasoning_effort` を揃えている。

## 2. 探索的分析（主張には使わない）

A4 − A3、A4 − A2、A4 − A0、A1 − A0、A5 − A0 の差と 95% CI。セッション別正答率、Q_inj / Q_natural の層別正答率、`stale` 率、誤答分類、memory probe 正答率、偽メモの残存率と訂正率、1 正答あたりの費用、CL-Bench の公式スコアと正答率。多重比較の補正は行わず、すべて「探索的」と明記する。

## 3. 固定する実験条件

| 項目 | 値 |
|---|---|
| 群 | A0, A1, A2, A3, A4, A5（定義は 00_design §4） |
| セッション / 問題 | 12 セッション × 6 問（縮小規則適用時は × 5 問） |
| migration | セッション 4・8 の後 |
| 誤メモ注入 | セッション 3・7 の後に 1 件ずつ（A1 / A3 / A4） |
| モデル | 全役割 `gpt-6-luna`。agent `reasoning_effort=low`、consolidator `medium` |
| 予算 | `configs/experiments/main.yaml` の `budgets` をそのまま使う |
| 解析対象 | 主解析は main のみ。ストリームを単位とし、全 6 群が完走したストリームだけを解析する。API 障害（`failed`）や予算到達（`budget_exhausted`）で 1 群でも完走しなかったストリームは、全群から除外して件数を報告する（群ごとの選択的除外はしない） |
| 未提出の扱い | 完走したストリーム内で、1 問の上限（ターン・クエリ・入力上限）に達して提出がなかった問題は `no_submission` の誤答として分母に含める |
| 停止規則 | 費用台帳が main の枠（$120、規模規則で予備を足した場合は $130）または絶対上限 $200 に達したら新しいストリームを始めず、その時点で全群が完走したストリームだけで解析する |
